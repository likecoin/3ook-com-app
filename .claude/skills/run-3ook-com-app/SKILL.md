# Run the 3ook.com app

Expo SDK 55 / RN 0.83 native shell: one full-screen `WebView` on
`https://3ook.com?app=1` plus native bridges (audio, IAP, identity, push,
attribution). `ios/` and `android/` are generated by `expo prebuild` and
gitignored — never hand-edit them.

Three harnesses live here. Pick by what you changed:

| Changed | Use | Cost |
|---|---|---|
| Pure logic in `services/` / `hooks/` — URL routing, host allowlists, attribution sanitizing, the persisted-URL store | `probe.mjs` | ~1 s, no build |
| Anything that must run inside the shell — WebView props, bridges, native modules, layout | `driver.mjs` (iOS Simulator) | build once, then seconds |
| Android-only behaviour — App Links, Custom Tabs, `cacheMode`, nav-bar insets, install referrer | `driver-android.mjs` (emulator) | same |

Both drivers take the same commands and share `driver-common.mjs`, which also
imports the app's own `services/external-hosts.ts` rather than re-stating its
host and path rules — the drivers exist to check that predicate, so a private
copy could drift and still report a pass. All paths below are relative to the
repo root. Verified on macOS (darwin 25.6), Xcode 26.6 + iOS 26.5 simulators,
Android SDK with a `Pixel_7a` API-36 AVD, Node v24.15.

## Prerequisites

Xcode with an iOS runtime, and the Node version in `.nvmrc` (24.10.0; 24.15
works). For the Android path: the Android SDK with platform-tools, an AVD, and
a JDK (Zulu 17 here). Nothing needed installing. Optional but assumed present:
`.env.local` supplies `INTERCOM_*`, `REVENUECAT_*`, `EXPO_PUBLIC_POSTHOG_*`,
`SENTRY_AUTH_TOKEN`. Expo CLI auto-loads it. Without it the app still runs;
Intercom and IAP just self-disable and `NATIVE_BRIDGE_FEATURES` drops `iap`.

## Direct invocation — no build (do this first)

`probe.mjs` imports the repo's TypeScript in bare Node. Node 24 strips types;
a small ESM resolve hook (`probe-loader.mjs`) adds the two things Metro does
that Node doesn't — extensionless relative imports and `.native.ts` platform
suffixes — and swaps `react-native` / `expo-*` / RevenueCat / Firebase for
inline stubs.

```bash
node .claude/skills/run-3ook-com-app/probe.mjs check
```

19 assertions over the URL/host decision table — bookstore vs app-bound vs
external-browser hosts, deep-link resolution, `app=1` enforcement, prototype
pollution in attribution keys, and a `last-url.json` round-trip through an
in-memory `expo-file-system` stub. Extend `check()` when you change that logic.

Ad-hoc:

```bash
node .claude/skills/run-3ook-com-app/probe.mjs -e "const m = await load('services/url-storage.native.ts'); console.log(m.resolveDeepLinkURL('https://3ook.com/en/reader/1?foo=bar'))"
# → https://3ook.com/en/reader/1?foo=bar&app=1
```

`load()` takes a repo-relative path. For anything longer, write a script and
`node .claude/skills/run-3ook-com-app/probe.mjs run /path/to/script.mjs`.
If a module you want imports a package with no stub yet, add one to `STUBS` in
`probe.mjs` — named exports must be declared statically (ESM links at compile
time, so a Proxy will not work).

## Run on the iOS Simulator (agent path)

First time, or after touching native config / `app.config.ts` / plugins /
`modules/`:

```bash
node .claude/skills/run-3ook-com-app/driver.mjs build
```

Wraps `npx expo run:ios`. **~15 min cold**, ~1 min incremental. It boots a
simulator, starts Metro, compiles, installs, and launches. JS-only edits after
that need no rebuild — Fast Refresh applies them.

Add `--release` for a Metro-free build with no LogBox overlay (good for clean
screenshots, no Fast Refresh, full rebuild each time).

Then drive it:

```bash
node .claude/skills/run-3ook-com-app/driver.mjs smoke
```

Three cold starts, one per URL-restore rule: a normal route is restored; a
browser-only subdomain and a bookstore path are not. ~22 s — it watches
`last-url.json` for the app's own post-navigation write rather than sleeping a
fixed interval. Exits non-zero on a dead app, a failed check, or an
unrecognised JS error.

**Read the screenshots.** They land in
`.claude/skills/run-3ook-com-app/.artifacts/shots/` (gitignored).

Individual commands:

```bash
D=.claude/skills/run-3ook-com-app/driver.mjs
node $D boot                    # boot iPhone 17 (or pass a name/UDID)
node $D metro                   # start Metro detached → .artifacts/metro.log
node $D goto /en/shelf          # point the WebView at a URL, then relaunch
node $D shot after-fix          # → .artifacts/shots/after-fix.png
node $D syslog 8 js             # 8s of the JS console (works in Debug + Release)
node $D logs 60                 # last 60 lines of Metro output (Debug only)
node $D syslog 8                # 8s of native os_log for the app process
node $D state                   # the app's Documents/*.json
node $D relaunch                # cold restart
```

### How navigation works — read this before trying anything else

There is **no tap automation** here. `goto` is the navigation primitive: it
writes `Documents/last-url.json` in the app's data container and relaunches,
because `getInitialURL()` (`services/url-storage.native.ts`) reads that file on
cold start. So `goto` exercises the app's own URL-restore path, and it is
deterministic.

`goto` warns when a URL is one `is3ookURL` rejects (bookstore `/store` paths,
`docs.3ook.com`, `publish.3ook.com`, non-https). That is not a driver failure —
that rejection *is* the behaviour under test, and the app falls back to
`https://3ook.com?app=1`.

## Run on the Android emulator

Same verbs, different file.

```bash
A=.claude/skills/run-3ook-com-app/driver-android.mjs
node $A doctor
node $A boot                    # start the first AVD, wait for boot_completed
node $A build                   # npx expo run:android (gradle)
node $A metro                   # start Metro detached (shared with iOS)
node $A smoke                   # same three cold starts + checks as iOS
node $A goto /en/shelf
node $A shot after-fix
node $A logs 60                 # ReactNativeJS logcat
node $A state                   # files/*.json, incl. install-referrer.json
```

**Android can fire real App Links, iOS can't.** This is the one way to verify
external-URL routing end to end:

```bash
node $A link https://3ook.com/en/store
node $A shot store-link
```

That opens the bookstore in a **Chrome Custom Tab** (browser chrome visible at
the top of the screenshot), not the WebView — which is exactly what
`openExternalURL` does for the app's own App Links on Android.

## Gotchas

- **Universal Links do not reach the app on the Simulator.**
  `xcrun simctl openurl booted "https://3ook.com/en/reader/1"` silently opens
  **Safari** instead — the `applinks:3ook.com` association is never verified
  on a simulator. This is why `goto` seeds `last-url.json` rather than using
  `openurl`. Deep-link *routing* logic is covered by `probe.mjs check`.
- **No taps.** `simctl` has no tap verb, `idb` is not installed, and
  AppleScript UI scripting fails with
  `execution error: "System Events" … not allowed assistive access. (-1719)`
  unless the terminal is granted Accessibility. Anything requiring a tap inside
  the WebView is out of reach; drive by URL instead.
- **LogBox toasts cover the bottom ~15% of Debug screenshots**, including the
  tab bar. They are RN's own overlay and cannot be dismissed headlessly.
  Use `driver.mjs build --release` for presentation screenshots.
- **Two JS log channels, and only one survives Release.** Metro's stdout
  (`driver.mjs logs`) exists in Debug only. React Native *also* mirrors every
  `console.*` into `os_log` under subsystem `com.facebook.react.log:javascript`
  in both configurations — that's what `syslog … js` and `smoke` read, so they
  work against either build. Plain `syslog` is native-side output, so noisy the
  driver filters three Apple subsystems out of it.
- **Simulators and emulators shut themselves down mid-run.** Both drivers'
  `smoke` re-boots instead of failing (the app survives a shutdown); other
  commands on Android still exit with `no Android device/emulator`.
- **Only `/en/…` locale prefixes resolve.** `/zh-Hant/shelf` and
  `/zh-Hant/account` both 404 on the site — Chinese is served from the
  unprefixed path plus a stored preference, so `goto /shelf` after an English
  session renders in English. Not a native bug; erase app data for a clean
  locale.
- **RevenueCat's `logOut … current user is anonymous`** is expected whenever
  nobody is signed in (the identity bridge calls `Purchases.logOut()` on reset).
  Both platforms log it, with different wording. `smoke` filters it.
- **The Android SDK's emulator is at `emulator_old/`, not `emulator/`.**
  `$ANDROID_HOME/emulator/emulator` does not exist on this machine, so
  `emulator -avd …` off `PATH` fails. `driver-android.mjs boot` probes all
  three known locations.
- **Play Billing is always unavailable on the emulator**, even on a
  `google_apis_playstore` image, because no Google account is signed in.
  RevenueCat then floods logcat with `BILLING_UNAVAILABLE`. `smoke` filters it;
  real IAP flows need a device.
- **`goto` on Android needs a Debug build** — it writes through
  `adb shell run-as`, which only works on a debuggable package.
- **A cold adb daemon reports zero devices on its first call.** Left unhandled
  this makes `boot` start a *second* emulator on top of a running one; the
  driver asks twice with a `start-server` in between.
- **logcat's ring buffer evicts `ReactNativeJS` within minutes** on a chatty
  emulator, so `node $A logs` can come back empty even though the app logged.
  Relaunch (`node $A relaunch`) and read again, or use `smoke`, which clears
  the buffer first.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `no Android device/emulator` | `node $A boot` (iOS auto-boots instead) |
| `land.liker.book3app is not installed` | `node $D build` / `node $A build` |
| App shows a blank/error screen, `logs` shows `ReferenceError: Property 'x' doesn't exist` | Real JS error from your edit — Fast Refresh already pushed it. Fix and it reloads. |
| `metro did not come up within 60s` | Stale Metro on the port: `lsof -ti:8081 \| xargs kill -9`, then `node $D metro` |
| `could not write files/last-url.json — run-as needs a Debug build` | The installed Android APK is a Release build; `node $A build` reinstalls Debug. |
| Metro warns about mismatched `expo-*` versions | Pre-existing in this repo; the app runs. `npx expo install --check` to reconcile. |

Two traps if you edit the harness itself: Metro must receive the log file
descriptor directly (`stdio: ['ignore', fd, fd]`) or `metro` never returns, and
`probe-loader.mjs` must label `.ts` files `'module-typescript'` — plain
`'module'` disables type stripping and you get `SyntaxError: Unexpected token ':'`.
